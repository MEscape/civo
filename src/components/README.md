# Shared components

Use existing composites before adding a new shared component. Business-specific components and hooks belong in their owning module.

- `ui/` contains styled primitives built on the individual `@radix-ui/react-*` packages (never the `radix-ui` umbrella package), including the Radix progress bar in `progress.tsx`, the Radix `switch.tsx` and the shadcn `breadcrumb.tsx` (`Breadcrumb`, `BreadcrumbList`, `BreadcrumbItem`, `BreadcrumbLink`, `BreadcrumbPage`, `BreadcrumbSeparator`).
- `text-inverse-action-copy` is reserved for text on `bg-primary-foreground` fills inside inverse sections; ordinary links use the existing readable `*-copy` tokens.
- `ui/` also holds `accordion.tsx` (Radix accordion), `alert.tsx` (`Alert`, `AlertTitle`, `AlertDescription`; success, warning, danger and info), `badge.tsx` (`Badge` and its variants), `input.tsx` (`Input`, `Label` and `Textarea`, the one visual contract of text controls), `radio-group.tsx`, `content-link.tsx` (a link whose target comes from content: not locale-prefixed, protocol-checked), `portal-container.tsx` (where floating layers open, so one opened inside a modal `<dialog>` stays inside it) and `chart-theme.ts` (the theme tokens as the strings Recharts takes).
- `ui/avatar.tsx` supplies image and initials fallbacks; fallback typography inherits the root's size. `ui/dropdown-menu.tsx` supplies keyboard navigation, focus restoration, dismissal, and portal-aware account menus through Radix.
- `brand/` holds the product's marks: `app-brand.tsx` (the admin bar's brand link), `artemis-logo.tsx` (the logo as paths, in the text colour) and `powered-by.tsx` (the quiet credit on a municipality's public site).
- `icons/` is one 24x24 stroke set: import from `icons.tsx` (`Icons` and named exports); `interface-icons.tsx` (controls and arrows) and `symbol-icons.tsx` (status, devices, contact, accounts) hold the shapes, `icon-factory.tsx` the shared canvas, and `dynamic-icon.tsx` draws an icon chosen by data from this set only.
- `page-states/` holds the bodies of every 404 (`not-found-panel.tsx`) and `error.tsx` (`route-error-panel.tsx`); route groups supply the text.
- `providers/i18n-provider.tsx` (server) and `i18n-client-provider.tsx` supply the namespaces a subtree translates with.
- `layout/` contains page frames and navigation: `layout-primitives.tsx` (`PageShell`, `AppHeader`, `SectionBar`, `Container`, `AdminContainer`, `Section` with its tones and densities, `PageHeading`, `SectionHeading`, `Grid` and `EmptyState`), `app-nav.tsx` and `section-nav.tsx` (the website bar and the booking workspace's bar: as many tabs as measured room allows, the rest in one dropdown; a tab can be switched off with a hint, `isDisabled`, or told it is current by its owner, `isActive`, where areas share an address prefix), `nav-disclosure.tsx` and `rail.tsx`. Stateful navigation behavior lives in `src/hooks/`; section navigation stays compact until its available width is measured.
- `layout/admin-page.tsx` is the frame of every admin screen: `AdminPage` (content column and one vertical rhythm) and `AdminPageHeader` (optional breadcrumb, the page's single `h1` with its lead, an optional `meta` slot for a detail screen's identity, and the main action at the far edge). Back navigation is the breadcrumb; only a screen reached from many others (the profile) has no parent, and passes `back` instead: `shared/page-parts.client.tsx` (`BackLink`), which returns to the page the person came from. `skeletons/admin-skeletons.tsx` mirrors it (`AdminPageSkeleton`, `DataPanelSkeleton`, `FormPanelSkeleton`, `WizardSkeleton`); screen skeletons are assembled from these.
- `layout/rail.tsx` aligns section headings beside their content using container queries. Section densities inherit through the shared section spacing token.
- `shared/javascript-required.tsx` is the no-script notice of screens that need JavaScript (sign-in, administration). It sits outside Suspense in the auth and protected layouts; public pages render complete HTML and never show it.
- Files of the shared library hold a whole family of components (up to 600 code lines, see `docs/rules/code-style.md`); merge a new component into its family's file instead of adding a file per component. The exception is the line between server and client: a file with `'use client'` cannot be merged into one that server code imports functions from.
- `shared/data-panel.tsx` owns list and form framing: `DataPanel` (a labelled region built on `ui/card`), `DataPanelBody`, `DataPanelFooter`, and `DataPanelSaveFooter`, the foot of every in-place edit form (unsaved, saved or refused on the left; Save, offered only when there is something to save).
- `shared/field.tsx` owns labeled text/textarea/checkbox controls (`TextField`, `TextareaField`, `CheckboxField`) and field feedback (`FieldMessage`, `FieldSuccess`). `select-field.tsx` owns the choice controls (client): `SelectField` and its form binding, the radio choice, and `AutocompleteField`, a combobox that only suggests (`use-autocomplete.ts` holds the keyboard behaviour): typed text is always kept, callers supply the options (addresses from `use-address-search.ts`, zones filtered locally).
- `shared/data-panel.tsx` also owns the overview blocks (`OverviewPanel`, rows and statistics, framed by `DataPanel`) and the linked `OverviewTile` figures with the responsive `OverviewTiles` grid. Modules supply their own labels and counts.
- `shared/point-map.tsx` draws places as pins (`MapPoint`: DOM buttons with an accessible name, a number or letter and a tone) on a Mapbox map loaded on demand, inside `map-canvas.tsx`. `use-point-map.ts` mounts it and owns the markers (`MarkerLayer`) and the `MapPoint` type; the camera only moves when the set of places changes. Callers pass a stable `points` array, hover/selection callbacks and the tile settings from `mapTiles()` (`@lib/config`).
- `shared/pagination.tsx` owns the page links below a list (`Pagination`), kept in a `DataPanel` footer. `pagination-buttons.client.tsx` is the same pager for a list that pages in the browser (a long list of exceptions, with `onPage` instead of links), and `pagination-parts.ts` the page window and styles both read: they stay apart because a client file cannot give the server one its functions.
- `shared/responsive-table.tsx` renders one accessible dataset as desktop rows or narrow-container cards, preserving row state and actions. The density classes (`DENSITY_CLASSES`) are in the same file, so the table and its loading skeleton read one source. A column's `width` (a responsive class such as `@3xl:w-56`) sets its share of the table, and `groupHeading` opens a group of rows (a day) with a heading that spans every column, or the whole card. Optional `rowDetails` content expands across every column through `TableRowDetailsTrigger` (`table-row-details.tsx`, which also holds the expandable row), retaining expansion on resize. Sortable headers use flex alignment in cards and table-cell alignment in desktop rows.
- `shared/wizard.tsx` owns multi-step forms for every module: `Wizard` (the frame with the step heading, progress and foot), `WizardSteps` (the indicator) and `WizardActions` (cancel, back, next or save). Callers supply translated step labels, the fields and the save; focus moves to the new step's heading through `hooks/use-step-focus`, and the step belongs in the address.
- `shared/filter-bar.tsx` owns list filtering in the address: `FilterBar` (GET form with apply and reset), `FilterSearchField`, `FilterSelect`, `FilterChips` (one-press quick filters for a small categorical dimension, above the bar), `ANY_FILTER_VALUE` and `SortLink` with `ariaSortOf` (a column heading that sorts, its arrow showing the direction). The same file holds `LinkTabs`, address-backed tabs for a page's own destinations (they look like `Tabs`, styled with the same `ui/tabs-styles.ts` strings, and wrap when the labels do not fit).
- `shared/dialog.tsx` owns the modals of the app, all on the platform's `<dialog>` and one frame (`hooks/use-modal-dialog.ts` holds the behaviour: shown as `open` says, focus on the way back, Escape answers "cancel" unless an action is pending): `InfoDialog` shows one thing with the actions on it (a booking's details); `DialogNotice` is how a dialog says something about its own state (a refusal, the problems of what was typed, a warning), the same box everywhere, also in a dialog that opens another; `ConfirmDialog` asks before something is given up or sent (title, optional description and body, a confirm action, destructive by default, and cancel); `DeleteWhenUnusedDialog` deletes, or says why not yet: it lists every use (`UnusedCheckUse`) with a link to where it is switched, and asks the ordinary question only when nothing uses it. Modules supply the uses and translated labels.
- `hooks/use-wizard-steps.ts` drives a `Wizard` over one react-hook-form form: the step in the address, per-step validation on Next, and errors (client or server) sending the person to the step that holds them.
- `shared/radio-card-group.tsx` is one choice from a few, each a card with a sentence of explanation, on `ui/radio-group.tsx`.
- `shared/process-steps.tsx` owns instructional steps (`ProcessSteps`), actionable onboarding checklists (`OnboardingChecklist`) and `ReadyForUseNotice`, which ends a setup whose last step happens in the page editor: a success note with one button to the component waiting for it (`?select=`), or the page list. Callers supply translated labels and decide completion.
- `shared/page-parts.client.tsx` holds the small interactive parts of a page (client): `BackLink` goes back to the page the person came from (the browser history), or to a fallback when the screen was opened directly; `CopyButton` (on `use-copy-to-clipboard`); `ClampedText` cuts a text to a few lines and offers a toggle only when it is really cut; `LoadingStatus` says once, to assistive technology, that a Suspense fallback region is loading. `layout/nav-disclosure.tsx` uses `use-nav-disclosure`.
- `providers/unsaved-changes-provider.tsx` coordinates dirty forms through `use-unsaved-changes` and the existing unload/navigation hooks.
- `providers/refresh-on-focus.tsx` mounts once in the protected layout and delegates visible-tab and window-focus refreshes to `use-refresh-on-focus`, coalescing signals within one second. It exposes no context because consumers need no shared state.
- `skeletons/responsive-table-skeleton.tsx` shares the loaded table density classes and supports column counts and mobile title columns. Booking fallbacks select the list shape; `booking-area-skeleton.tsx` mirrors location selection, and `booking-form-page-skeleton.tsx` mirrors create wizards and single-part edits.
- `skeletons/` contains screen-specific loading layouts, one per screen that streams (`audit-page-skeleton.tsx`, `auth-form-skeleton.tsx`, `builder-editor-skeleton.tsx`, `builder-pages-skeleton.tsx`, `data-source-detail-skeleton.tsx`, `map-editor-skeleton.tsx`, `maps-page-skeleton.tsx`, `media-page-skeleton.tsx`, `release-preview-skeleton.tsx`, `releases-page-skeleton.tsx`, `users-page-skeleton.tsx`, `website-overview-skeleton.tsx`, `website-settings-skeleton.tsx` and `websites-page-skeleton.tsx`). Match the content that follows rather than using a global page placeholder (`booking-page-skeleton.tsx`, `booking-form-page-skeleton.tsx` and `booking-screens-skeleton.tsx` hold one placeholder per kind of booking screen: lists with or without filters, location-scoped lists with their "Working at" row, the services' categories, overview, calendar, detail, and the wizard (`steps`: 5 for a location or service, 3 for a resource) or one-part edit form (`steps` 0); `employee-screens-skeleton.tsx` holds the employee's start, plan, preferences and profile, and a manager's view of one employee). Published citizen pages have no skeletons: they render complete HTML (see `docs/rules/nextjs.md`).
- `skeletons/profile-page-skeleton.tsx` mirrors the personal details form and account information panel.
- `skeletons/section-bar-skeleton.tsx` is the bar under the app header while it loads, one for the platform, a website and a booking workspace alike (an optional name, the number of tabs, and the link at the end where there is one), so all three bars arrive without a jump. `skeletons/booking-skeleton-parts.tsx` holds what every booking skeleton is built from: the screen frame in `AdminPage`'s rhythm, the framed panel, the filter strip, the note a page opens with and the table.
- `skeletons/data-sources-page-skeleton.tsx` mirrors connected sources with their setup guide; `data-source-form-skeleton.tsx` mirrors the source and dataset wizard frame.

Shared components receive translated text and never import business modules. Colors, radii, focus indicators and reduced-motion behavior follow the application tokens.
