**WUE-030 — High, Confirmed (fixed 2026-11-09):** Root cause: the public route streamed through two `loading.tsx` boundaries and per-block `<Suspense>`, so content arrived as `div[hidden]` segments revealed only by inline scripts. The route now sets the documented `instant = false` (blocking render), has no loading boundary, and the renderer no longer wraps blocks in Suspense. The JavaScript-required notice moved from the root layout to the auth/admin layouts. Real Chromium with JavaScript off passed all 12 public pages at 320px against both `next dev` and a production `next start` (zero hidden segments, one visible H1 and main). Guarded by `__tests__/architecture/public-pages-complete-html.test.ts`. Original finding: With scripting disabled, the streamed public site returned HTTP 200 with hidden content and no visible text. Public loading now announces progress, and a root-level no-script explanation renders outside the streamed provider. Full content/map/list access without JavaScript remains open. Evidence: `verification/accessibility-modes.json`, `verification/no-script.png`, `verification/no-script-fallback.png`. No workaround using private framework IDs or user-agent spoofing was added. The documented Next.js `htmlLimitedBots` option controls metadata streaming; it is not evidence of a complete no-script content solution, and no global bot override was introduced.
